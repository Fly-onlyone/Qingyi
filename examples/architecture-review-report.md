**Impact**: Dedicated server crash when apocalypse event fires

**Recommended Fix**:
```java
@SubscribeEvent
public static void onApocalypseStart(ApocalypseStartEvent event) {
    // Use network packet to notify client
    if (event.getLevel() instanceof ServerLevel serverLevel) {
        serverLevel.players().forEach(player -> {
            player.displayClientMessage(
                Component.literal("The apocalypse begins!"), true
            );
        });
    }
}
```

**Why This Matters**: The `Minecraft` class only exists on the client. When this code runs on a dedicated server, it throws `ClassNotFoundException` and crashes the server.

**Recommendation**: Add tick throttling for expensive operations:
```java
private static int tickCounter = 0;
private static final int SPAWN_INTERVAL = 100; // Every 5 seconds

@SubscribeEvent
public static void onServerTick(TickEvent.ServerTickEvent event) {
    if (event.phase == TickEvent.Phase.END) {
        tickCounter++;
        if (tickCounter >= SPAWN_INTERVAL) {
            tickCounter = 0;
            spawnTNTWave(event.getServer());
        }
    }
}
```

## Recommended Patterns

### For Boss Bar Management

**Suggested Pattern**: Observer Pattern with Event-Driven Updates

**Rationale**: Boss bars need to sync with multiple players and respond to apocalypse state changes.

**Implementation Example**:
```java
public class ApocalypseBossBarManager {
    private static final Map<UUID, ServerBossEvent> activeBars = new HashMap<>();

    public static void updateProgress(float progress) {
        activeBars.values().forEach(bar -> bar.setProgress(progress));
    }

    public static void addPlayer(ServerPlayer player) {
        ServerBossEvent bar = activeBars.computeIfAbsent(
            player.getUUID(),
            uuid -> new ServerBossEvent(
                Component.literal("Apocalypse Countdown"),
                BossEvent.BossBarColor.RED,
                BossEvent.BossBarOverlay.PROGRESS
            )
        );
        bar.addPlayer(player);
    }
}
```
